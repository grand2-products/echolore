EchoLore は MCP (Model Context Protocol) サーバーを内蔵しており、ChatGPT や Claude などの外部 AI エージェントを Wiki ナレッジに接続できます。

## できること

| ツール | スコープ | 機能 |
|--------|---------|------|
| `wiki_search` | read | Wiki のベクトル検索 |
| `wiki_read_page` | read | ページ本文を Markdown で取得 (長文はページング対応) |
| `wiki_list_spaces` | read | スペース一覧と書き込み可否の確認 |
| `wiki_list_pages` | read | ページ一覧 (更新順・スペース絞り込み・階層付き、棚卸しに) |
| `wiki_maintenance_report` | read | ナレッジ監査 (レビュー期限超過・停滞・空ページ等) |
| `wiki_create_page` | write | Markdown からの新規ページ作成 |
| `marketing_query_metrics` | reporting | マーケティング指標の集計 (費用・CV・セッション等 + CPA/ROAS 等の派生指標) |
| `marketing_list_dashboards` | reporting | レポーティングダッシュボード一覧 |
| `marketing_get_dashboard` | reporting | ダッシュボード定義 (ウィジェット・指標・フィルタ) |
| `marketing_data_status` | reporting | データ鮮度・同期健全性・承認待ちの確認 |

読み取りツールはトークン発行者の読み取り権限でフィルタされ、読めないページの情報は返りません。
マーケティングツールはトークン発行者が `marketing.view` 権限を持っている必要があります。
ツール実行はトークンごとにレート制限 (5分間で60回) が適用されます。

### レポーティングダッシュボードを GUI なしで使う

`reporting` スコープ付きトークンを発行すれば、ChatGPT や Claude に
「先週の広告費とCPAをまとめて」「今月のダッシュボードをレポートして」のように
依頼するだけで、ダッシュボード定義の取得 → 指標クエリ → レポート組み立てを
エージェントが行います。集計挙動 (未取得日はゼロ扱いしない、媒体CVは合算しない、
複数通貨は通貨別) は Web UI と同じ API なので、数字の解釈も GUI と一致します。

## 接続方法

### OAuth 対応クライアント (ChatGPT / Claude コネクタ等)

OAuth 2.1 認可サーバーを内蔵しているため、認可サーバー URL として `https://<あなたのドメイン>` を指定するだけで接続できます。初回接続時に管理者同意画面が表示され、許可するとトークンが自動発行・自動更新されます (アクセストークン 30日、リフレッシュ時に自動ローテーション)。

### Bearer トークン (手動発行)

1. 管理画面 → **AI 設定** → **外部 AI エージェント接続 (MCP)** を開く
2. トークン名・スコープ (`read` / `write` / `reporting`)・有効期限 (無期限/7/30/90日) を選んで発行
   - 既定は `read` (最小権限)。ページ作成を許可する場合のみ `write`、マーケティングレポートに `reporting` を追加
3. 平文トークン (`ech_agt_...`) は**発行時に一度だけ表示**されるのでコピーして保管

トークンは発行した管理者の権限で動作します。失効させるといつでも即座に無効化できます。
各トークンの直近の利用履歴 (成功/失敗・ツール・日時) も管理画面から確認できます。

MCP 対応クライアントに以下を設定します:

```json
{
  "mcpServers": {
    "echolore": {
      "type": "http",
      "url": "https://<あなたのドメイン>/mcp",
      "headers": {
        "Authorization": "Bearer ech_agt_..."
      }
    }
  }
}
```

## プロトコル仕様

- プロトコルリビジョン **2026-07-28** (stateless MCP) 専用
  - `initialize` ハンドシェイク方式 (旧リビジョン専用クライアント) には非対応
- Streamable HTTP・ステートレス、POST のみ
- `server/discover` で対応バージョン・能力を広告
- 構造化出力 (`outputSchema` / `structuredContent`) とツール annotations に対応
- 認証は Bearer トークンのみ (OAuth 2.1 で発行されたトークンも同一形式)

## Agent Skills

リポジトリの `skills/echolore-wiki-maintenance/SKILL.md` に、エージェントに読み込ませるナレッジメンテナンス用スキル定義が同梱されています。監査・調査・記事化のワークフローと、ページ作成ツールの利用規律 (明示依頼時のみ) が定義されています。

## セキュリティの要点

- トークンは SHA-256 ハッシュでのみ保存 (平文は再表示不可)
- トークンに有効期限を設定可能 (OAuth 経由のトークンは必ず 30日)
- トークン発行者のアカウントが削除・停止されると自動無効化
- ページ作成は常に「発行者が作成者」として記録され、監査ログに残る
- OAuth 同意は管理者のみ。認可コードは PKCE 必須・一回限り、リフレッシュトークンは使用ごとにローテーション
- 既存ページの編集ツールは提供されない (破壊的操作のため)
